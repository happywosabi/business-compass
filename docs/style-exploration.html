开工写前端之前，先定页面长什么样、怎么动。这一页有三个风格方向和两个关键交互，都可以直接点。

手机里的数字都由计算引擎算出，用的是文档里的奶茶店例子。手机画面固定为浅色，因为第一版不做深色模式。

三个风格方向

三部手机画的是同一个页面：测算结果。点「播放出场动画」看每个方向的动效性格；点「差 / 一般 / 好」切换曲线；手指或鼠标在曲线上滑动，可以看每个月手里有多少钱。动画播放时点一下屏幕就能跳过。

新功能，需确认

在结果页直接拖动客单价和每天卖多少，曲线、每月赚多少、第几个月收回投入都跟着变。用户自己就能发现：价格少 7% 比客人少 10% 还伤。这是最能体现「罗盘」作用的一个交互。

正式产品里，拖动时把新数字发给服务器上的计算引擎去算，几毫秒就能算完。这里为了演示，用网页里的同一套公式。

动效原则

动画多了好看，乱了就累。下面 6 条决定什么时候动、怎么动。

  • 只在三种时刻动点了有反应（反馈），改了数字看到后果（因果），测算结果出来（揭晓）。其他时候保持安静。
  • 要快按钮、弹窗 150 到 300 毫秒。结果出场整套不超过 1.5 秒，点一下屏幕就能跳过。
  • 不为动画让人等罗盘转动只在后台真的在计算、AI 在写解读的时候出现，算完立刻停。
  • 坏消息不配欢快的动画回不了本时不弹跳、不盖「能回本」的章，结果平稳地出现，红色提醒同时配图标和文字。
  • 便宜的手机也要流畅只动位置、大小、透明度，这几样最省性能。同一屏同时动的不超过三组。千元安卓机和微信内置浏览器都要实测。
  • 尊重系统设置手机开启「减少动态效果」后，所有动画关闭，直接显示结果。这一页也是这样做的。

怎么实现

不引入 GSAP、Lottie 这类动画库。上面的效果都用不到它们，加了反而让第一次打开变慢。

动效做法增加的体积
页面切换、弹窗、列表出现Vue 自带的 Transition，加 CSS0
按钮按下、骨架屏Vant 自带，加 CSS0
数字滚动自己写一个小组件，约 30 行0
罗盘指针SVG 图形加 CSS 动画0
曲线绘制、切换「差 / 一般 / 好」ECharts 自带动画已含在 ECharts 里
「已记录」飞进档案卡片浏览器自带的 Web Animations0
数字字体放在自己的服务器上，只含英文字母和数字约 20 KB

中文用手机系统自带的字体，比如苹果的苹方、华为的鸿蒙黑体、小米的 MiSans。中文网络字体动辄几 MB，Google 字体在国内也打不开。品牌感放在数字上：这个产品的主角就是数字，一款几十 KB 的数字字体就能和别的应用区分开。

需要你选

  1. 风格方向：A 罗盘（我推荐）、B 明快、C 小票。也可以以 A 为主，只在测算结果页借用 C 的打小票和盖章。
  2. 「拖一拖」要不要放进第一版：后端只要加一个接口，计算引擎里已经有现成的假设性测算。
  3. 6 条动效原则是否同意。
