## 二、计算引擎 `backend/app/engine/`

### 2.1 依赖规则

- 引擎**只做计算**：输入参数，输出结果。不读文件、不连数据库、不调用 AI、不访问网络
- 需要的外部数据（如经验阈值）由调用方读好后传进来
- 引擎目录不允许引用 `app` 下的其他模块，用一个测试自动检查
- 好处：测试不需要启动 Docker、数据库；同样的输入永远得到同样的结果

### 2.2 文件清单

| 文件 | 职责 | 对应文档 |
|---|---|---|
| `__init__.py` | 对外只暴露三个入口：`evaluate`、`what_if`、`estimate_traffic` | |
| `version.py` | 引擎版本号（如 `1.0.0`），写入每份评估快照 | 数据结构 第七节 |
| `params.py` | 参数结构：三档参数值、实体小店参数清单；硬性校验（不能为负、比例在 0–1 之间、悲观/乐观为空时等于中性） | 数据结构 6.1、6.2 |
| `inputs.py` | 把三档参数转换成某一个情景（悲观 / 中性 / 乐观）的计算输入；计算推导值：押金金额、装修期房租、比例费率 f、每月固定成本 F(t)、产能上限、可收回 / 不可收回投入 | 测算模型 第二节 |
| `projection.py` | 逐月推演现金曲线；算出开始不亏钱的月份、现金最低点、建议准备资金、回本月份、租约检查 | 测算模型 3.2、3.3 |
| `thresholds.py` | 单变量临界值（保本日单量、保本客单价、临界按单成本、临界房租）和安全边际 | 测算模型 3.4 |
| `sensitivity.py` | 敏感性分析：每次只让一个参数取悲观值 / 乐观值，其他保持中性，排出最怕的 3 个变量 | 测算模型 第六节 |
| `checks.py` | 合理性检查：接待能力、成本率、房租占比、人手等；阈值由调用方传入 | 测算模型 第四节 |
| `traffic.py` | 客流估算三种方法：选址法、对标法、产能反推 | 测算模型 第五节 |
| `results.py` | 输出结构，字段与数据结构文档第七节的 results 一一对应 | 数据结构 第七节 |
| `evaluate.py` | 总入口：三种情景 → 逐月推演 → 临界值 → 敏感性 → 合理性检查 → 组装结果；`what_if` 也在这里 | |

### 2.3 三个对外入口

| 入口 | 输入 | 输出 | 谁会调用 |
|---|---|---|---|
| `evaluate` | 完整的实体小店参数、经验阈值 | 完整评估结果（三种情景、临界值、敏感性、检查结果） | AI 工具 run_evaluation、"重新测算"接口 |
| `what_if` | 当前参数、临时修改、经验阈值 | 修改前后的对比，不保存 | AI 工具 what_if |
| `estimate_traffic` | 估算方法及输入、业态默认值（进店率、成交率等） | 日均单量估算值及范围 | AI 工具 estimate_traffic |

参数不完整时，`evaluate` 不做任何猜测，直接返回缺失的参数清单。补默认值是调用方的事（见第三节）。

### 2.4 数值约定

- 引擎内部用普通浮点数计算，只在输出展示时取整
- 测试中比较金额允许 0.01 元误差
- 保本日单量展示时向上取整（146.83 → 147 单，"至少要卖"）
- 逐月推演：结果中保存前 36 个月的逐月数据；计算回本时最多推演 120 个月
- 季节系数对齐：第 t 个月对应的自然月 = (开业月份 + t − 2) mod 12 + 1

### 2.5 对测算模型的一处细化（已确认）

测算模型第六节写的是"按对**回本月份**的影响排序"。实现时发现一个问题：悲观情况下，很多参数都会让结果变成"120 个月内无法回本"，这些参数之间就没法比较大小了。

建议改为按对"**第 36 个月末手里的钱**"的影响排序：
- 它同时反映启动投入（如装修超支）和每月盈亏（如客流不足）
- 一定有数值，不会出现"无法回本"导致无法比较的情况
- 展示给用户时，仍然同时给出回本月份的变化

## 三、模板配置 `backend/app/templates/`

```
templates/
├── loader.py                 读取 YAML；按业态给参数补默认值，并返回补了哪些
└── physical_store/
    ├── parameters.yaml       参数清单：中文名、单位、访谈阶段、问法、是否快速必填（访谈流程第十五节）
    ├── defaults.yaml         各业态默认值：爬坡、季节系数、成本率、平台费率等（第一版先填饮品）
    └── checks.yaml           经验比例阈值（第一版先填饮品，数值标注"待核实"）
```

**分工**：
- 硬性约束（不能为负、比例在 0–1 之间）写在代码里（`engine/params.py`），因为这是数学上的要求
- 问法、默认值、经验阈值写在 YAML 里，因为它们是内容，需要经常调整，改了不用动代码

## 八、项目骨架（第二阶段）

### 8.1 服务

| 服务 | 镜像 | 说明 |
|---|---|---|
| db | pgvector/pgvector:pg17 | PostgreSQL 17 + pgvector；数据存在 `pgdata` 数据卷 |
| api | 由 `backend/Dockerfile` 构建 | FastAPI；启动时先执行 `alembic upgrade head` |
| nginx | nginx:1.28-alpine | 唯一对外入口；转发 `/api/`，托管静态网页；登录注册接口按 IP 限流 |

- 只有 nginx 对外开放端口（`HTTP_PORT`，本机默认 8080）
- 本机开发时，`compose.dev.yaml` 把数据库端口映射到 `127.0.0.1:5432`，供本机运行测试；服务器上不加载它
- 第二阶段暂不包含 worker 和 hotapi，到内容生成阶段再加

### 8.2 后端模块

| 位置 | 职责 |
|---|---|
| `app/main.py` | 创建应用（`create_app`），测试时可传入自己的配置和邮件发送器 |
| `app/config.py` | 全部配置来自环境变量（`.env`）；密钥用 `SecretStr`，不会出现在日志里 |
| `app/db/` | 表定义（`models.py`）、数据库连接、Alembic 迁移 |
| `app/auth/` | 密码规则和哈希、令牌、注册登录业务逻辑、接口、"当前用户"依赖 |
| `app/mail/` | 邮件内容、SMTP 发送（阿里云邮件推送，465 端口 SSL） |
| `app/api/health.py` | 健康检查 |

数据库访问使用 SQLAlchemy 2.0 异步模式 + asyncpg，因为以后 AI 回复的流式输出需要异步。

### 8.3 登录注册接口

| 接口 | 说明 | 需要登录 |
|---|---|---|
| `POST /api/auth/register` | 注册，发送验证邮件 | |
| `POST /api/auth/verify-email` | 验证邮箱（邮件链接打开 `/verify-email` 页面后调用） | |
| `POST /api/auth/resend-verification` | 重新发送验证邮件（60 秒一次，每天最多 10 封） | ✓ |
| `POST /api/auth/login` | 登录，设置会话 Cookie | |
| `POST /api/auth/logout` | 退出当前设备 | |
| `GET /api/auth/me` | 当前用户 | ✓ |
| `POST /api/auth/forgot-password` | 发送重置密码邮件（无论邮箱是否注册，回复都一样） | |
| `POST /api/auth/reset-password` | 用邮件链接重置密码，所有设备退出 | |
| `POST /api/auth/change-password` | 修改密码，其他设备退出 | ✓ |
| `GET /api/health` | 健康检查 | |

其他接口要求登录时，在参数里写 `user: CurrentUser`；要求已验证邮箱（AI 功能）时写 `user: VerifiedUser`。

**实现中做的决定**：
- 注册时如果邮箱已注册，直接提示"该邮箱已注册"。数据结构文档只要求"忘记密码"不暴露邮箱是否注册；注册时直接提示对用户更友好，批量探测由 Nginx 限流挡住
- 重置密码成功时，如果邮箱还没验证，顺便标记为已验证（能收到重置邮件，说明邮箱属于本人）
- 新发的验证 / 重置链接会让同类的旧链接失效
- 会话的"最近活跃时间"最多 10 分钟更新一次，避免每个请求都写数据库

### 8.4 测试

| 目录 | 内容 | 需要数据库 |
|---|---|---|
| `tests/engine/`、`tests/templates/` | 计算引擎、模板配置 | |

### 9.2 实现中做的决定

- **注册成功后自动登录**，直接进入应用；顶部提示条提醒验证邮箱。比"注册 → 去邮箱 → 回来登录"少一步
- **登录后回到原来要去的页面**（网址里的 `?redirect=`）。只允许本站路径，防止被人构造链接跳到假冒网站
- **登录过期**（或在别的设备改了密码）时，任何接口返回 401 都会回到登录页，登录后回到原页面
- **Nginx 安全策略（CSP）**：网页只允许加载本站的脚本、样式和字体。只加在网页上，不加在 `/api/` 上（接口文档要从外部加载脚本）
- Vant 图标字体已内嵌在 CSS 里，打包时删掉了它指向 at.alicdn.com 的备用地址，不依赖外部网站
- TypeScript 固定在 5.9：7.0 是新的原生版本，类型检查工具还不支持
- 用户协议和隐私政策是**草稿**（`src/content/legal.ts`），上线前要补运营方信息和联系方式，并请律师审阅；改完把 `DRAFT` 设为 `false`

### 9.3 已验证

- 类型检查、45 个单元测试通过；Docker 构建（构建时也会做类型检查）通过
- 用无界面浏览器在手机（390px）、平板（1000px）、桌面（1440px）宽度下截图检查：登录、注册、表单校验、登录后跳回、我的、修改密码、退出登录确认、重置密码、失效的验证链接、协议页、404；没有页面横向溢出，浏览器没有报错
- 还没有在真实手机和微信内置浏览器上测试（需要部署到服务器后进行）



## 果园经营扩展（2026-11-05）

`engine/orchard.py`负责纯计算与校验；`templates/orchard/parameters.yaml`负责字段与问法；`templates/registry.py`分发参数类型、计算和试算。档案、测算、报告、访谈按template_key分流，沿用原URL。`interview/orchard.py`提供专用提示、换算和防误删/丢ID校验。前端OrchardForm/OrchardNumber及OrchardResultPage提供独立编辑/结果，小店结果保留在StoreResultPage，由ResultPage分发。OpenAPI声明重新生成。

字段、公式及边界见[果园经营测算模型](果园经营测算模型.md)。
