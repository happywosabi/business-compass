> 相关文档：[产品规划](产品规划.md)、[AI 访谈流程](AI访谈流程.md)（第十、十二节）、[代码结构](代码结构.md)

## 一、原则

- **手机优先，桌面端也认真做**：先按 375px 宽的手机屏幕设计；电脑上用专门的桌面布局（见第十二节），同一套代码按屏幕宽度切换
- **照顾小店主**：字号比常见网页大一号（正文 16px），按钮够大（至少 44px 高），能点选的地方不让用户打字
- **数字由代码渲染，AI 只负责解读**：要准备多少钱、第几个月回本这些关键数字，直接从评估快照里取出来展示，不经过 AI（与访谈流程 10.1 一致）
- **说大白话**：页面文字和 AI 用同一套说法，不出现"现金流""LTV""毛利率"，而是"每月赚多少""手里的钱""每单赚多少"
- **少依赖、选主流**：每个库都要有充分理由；优先选中文资料多、AI 编程助手熟悉的
- **要在微信里能用**：小店主常在微信里打开链接，测试时要覆盖微信内置浏览器

## 二、技术选型

| 部分 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3 + Vite | 中文资料最多，上手快；Vite 打包快、开发时改代码页面立刻刷新 |
| 语言 | TypeScript | 接口字段写错时编译就报错，不用等到用户点出问题 |
| 手机组件库 | Vant 4 | 有赞出品的手机端组件库：按钮、表单、底部弹窗、标签栏、提示框都现成 |
| 路由 | Vue Router | 官方 |
| 状态管理 | Pinia | 官方；只存当前用户和当前档案这类少量全局数据 |
| 图表 | ECharts（按需引入，只引折线图） | 国内最常用，中文文档全；按需引入后体积可控 |
| AI 文字渲染 | markdown-it（关闭 HTML） | AI 报告是 Markdown；关闭 HTML 后，AI 输出里即使夹带 `<script>` 也只会当文字显示 |
| 接口类型 | openapi-typescript | 从后端的 `/api/openapi.json` 自动生成 TypeScript 类型，后端改字段，前端编译时就能发现 |
| 网络请求 | 浏览器自带 fetch，自己封装一层 | 不需要 axios；流式输出也要用 fetch 读取 |
| 测试 | Vitest | 测数字格式化、流式数据解析这类纯函数 |

**不用的**：
- Nuxt / 服务端渲染：应用页面都要登录才能看，不需要搜索引擎收录
- Tailwind 等样式框架：Vant 已经提供了组件和主题变量，再加一套会重复
- 以后如果要做给搜索引擎看的介绍页（落地页），单独做一个静态页面即可

- **流式显示**：AI 回复逐字出现，不让用户干等
- **"已记录"小提示**：AI 每次写入参数，对话里插一条小提示，档案卡片同步刷新。用户一眼就能看出 AI 有没有理解错，点提示可以直接修改
- **快捷按钮**：点一下等于发送这句话
- **"先算一下"**：快速测算的必填项齐了才出现
- **断线 / 刷新不丢内容**：对话存在服务器，重新打开接着聊
- **语音输入不自己做**：手机输入法自带语音键，小店主习惯用；页面上提示一句"可以用输入法的语音输入"即可
- **键盘弹出不遮挡输入框**，并适配 iPhone 底部的安全区

### 4.3 档案卡片和参数修改

- 参数按访谈阶段分组：卖什么 / 铺面和装修 / 人和日常开销 / 客流
- 每行显示：中文名、数值、来源标签（**你填的** / **AI 估算** / **默认值**，用不同颜色加文字区分）
- 有三档时显示为"1.1 万（1 万–1.2 万）"
- 点击 → 从底部弹出修改面板：一般 / 差的时候 / 好的时候三个输入框，下面显示说明（如默认值的来由）
- 渠道结构、员工这类列表参数，用专门的小表单（加一行、删一行）
- 保存后提示："数据有变动，要重新算一下吗？"

## 六、视觉风格：方向 A「罗盘」（已选定）

> 三个方向的对比和可交互演示见 `docs/style-exploration.html`

- **气质**：沉稳、可信，像一件导航仪器
- **颜色**：
  - 主色深海蓝 `#10263d`：文字、主按钮、曲线
  - 点缀黄铜色 `#a87428`（做文字用时加深为 `#7a5318`）：罗盘指针、收回投入的标记、"已记录"标签、进度条
  - 背景 `#ecf1f5`，叠一层很淡的航海图网格；卡片为白色，用 1px 细边框区分，少用阴影
  - 状态色：绿 `#1d7348` 好、橙 `#9a520b` 提醒、红 `#b3261e` 危险，都配图标和文字。红色只用在"亏钱"上
- **字体**：中文用手机系统字体；数字用 Barlow Semi Condensed（窄体仪表风格，自托管，只含英文和数字，约 20 KB）
- **字号**：手机正文 16px；桌面正文 15px，阅读区（对话、AI 解读）16px；关键数字手机 27px 以上、桌面 34px
- **圆角**：卡片 10–12px，按钮 8px，标签全圆角
- **图表**：曲线 2px 深海蓝；零线实线；"收回线"为黄铜色虚线（押金和备货可退回，曲线越过它即收回投入）；标记点 9px；悬停或手指滑动显示每个月的数

### 6.1 动效原则（已确认）

1. 只在三种时刻动：反馈、因果、揭晓
2. 要快：按钮、弹窗 150–300 毫秒；结果出场整套不超过 1.5 秒，点一下可跳过
3. 不为动画让人等：罗盘只在真正计算时出现
4. 坏消息不配欢快的动画
5. 便宜的手机也要流畅：只动位置、大小、透明度；同屏同时动的不超过三组
6. 尊重系统的"减少动态效果"设置

### 6.2 标志性动效

| 时刻 | 动效 |
|---|---|
| 测算中 | 罗盘指针转动、晃几下后定住 |
| 结果出场 | 卡片依次上浮，数字滚动，曲线从左往右画出，标记点淡入 |
| AI 记下一个数 | "已记录"标签飞进档案卡片对应的那一行，那一行闪一下，进度加一 |
| 切换差 / 一般 / 好、拖动数字 | 曲线平滑变形，坐标轴跟着变 |
| 页面切换 | 手机左右推入；桌面淡入加轻微上移 |

实现方式：Vue Transition + CSS + 浏览器自带的 Web Animations，不引入动画库。

## 七、与后端的配合

- **同一个域名**：网页和 `/api` 都经过 Nginx，Cookie 自动带上，不需要跨域配置
- **登录状态**：靠后端设置的 HttpOnly Cookie，前端不保存任何令牌；打开网页时请求 `/api/auth/me` 判断是否已登录
- **统一错误处理**（写在 `src/api/client.ts`）：
  - 401 → 跳到登录页
  - 403"请先验证邮箱" → 显示验证提示条
  - 429 → "操作太频繁，请稍后再试"
  - 网络断开 → "网络不好，请稍后重试"
- **流式输出**：后端用 POST 返回 `text/event-stream`，前端用 fetch 逐段读取（浏览器自带的 EventSource 只支持 GET，不适用）。Nginx 已关闭 `/api/` 的缓冲
- **安全**：
  - AI 生成的内容和用户输入一律当文字显示，**禁止直接插入 HTML**（Vue 的 `v-html` 只允许用于 markdown-it 关闭 HTML 后的输出）
  - 不在 localStorage 里存敏感数据（商业档案、对话）
- **Nginx 调整**：
  - 网页路由都返回 `index.html`（单页应用），`/api/` 不变
  - 打包出的 js、css 文件名带内容哈希，可以长期缓存；`index.html` 不缓存，保证发布后用户拿到新版本

## 九、开发环境

- 本机的 Node 是 v12，Vite 需要 Node 20 以上。用 nvm 安装 Node 22：装在你的用户目录里，不需要 sudo，不影响系统已有的 Node 和 ROS
- 开发时：
  1. `docker compose up -d` 启动后端
  2. `cd frontend && npm run dev` 启动前端开发服务器（http://localhost:5173），`/api` 请求自动转发到 8080
  3. 改代码后页面立刻刷新
- 先用浏览器开发者工具的"手机模式"看效果；部署到服务器后，再用真机和微信内置浏览器测试

## 十、实施顺序

很多页面依赖还没写的后端接口，所以前后端交替推进：

| 步骤 | 前端 | 后端 |
|---|---|---|
| 1 ✓ | 前端骨架（含手机底部导航、桌面侧边栏两套外框）、登录注册 4 页、"我的"页、协议页；Nginx 改为单页应用；多阶段构建。替换临时测试页 | 已有 |
| 2 | 档案列表、新建档案、档案卡片（查看和修改参数） | 档案增删改查接口 + 越权测试 |
| 3 | 测算结果页（数字卡片、现金曲线、最怕的变量、提醒） | 测算接口：补默认值 → 计算引擎 → 保存快照 |

## 十二、桌面端（已确认）

> 可交互原型：`docs/desktop-prototype.html`（登录、我的档案、访谈工作台、测算结果四页，顶部「设计要点」按钮可看每页说明）

### 12.1 原则

- **同一套代码、同一个网址**，按屏幕宽度切换布局，不另做电脑版网站
- **不是把手机页面放大**：多出来的宽度用来让相关的东西同时可见，比如对话和档案并排、曲线和"拖一拖"并排，还有手机上放不下的逐月明细表
- 风格、颜色、字体、动效与手机端一致（方向 A）

### 12.2 三档宽度

| 屏幕宽度 | 布局 |
|---|---|
| 小于 768px | 手机布局：底部导航，单栏 |
| 768–1023px | 左侧窄导航（只有图标），单栏 |
| 1024–1199px | 左侧窄导航，页面分两栏 |
| 1200px 及以上 | 左侧导航 232px（带文字和档案列表），页面分两栏；内容最宽 1280px，超宽屏居中 |

### 12.3 手机和桌面的差异

| | 手机 | 桌面 |
|---|---|---|
| 导航 | 底部标签栏 | 左侧导航栏，可以直接切换档案 |
| 访谈 | 档案卡片折叠在顶部 | 档案卡片常驻右侧；"已记录"标签飞进对应的那一行 |
| 修改参数 | 底部弹出面板 | 就地弹出的小浮层 |
| 测算结果 | 从上到下一列 | 两栏：左边大曲线和 AI 解读，右边"拖一拖"、最怕的 3 件事、合理性检查；下方逐月明细表和数字来源 |
| 看每个月的数 | 手指在曲线上滑动 | 鼠标悬停，同时显示当月赚或亏多少 |
| 页面切换 | 左右推入 | 淡入加轻微上移 |
| 输入 | 输入法的语音键 | Enter 发送、Shift + Enter 换行；中文输入法选字时按 Enter 不发送；Esc 关闭浮层 |
| 悬停效果 | 无 | 档案卡片轻微上浮，按钮边框变深 |

### 12.4 页面

- **登录**：左边深海蓝底介绍产品（"聊一聊 → 算一算 → 盯住最怕的"三步），右边表单，登录和注册在同一位置切换。很多人从分享链接进来，第一眼要知道这是干什么的
- **我的档案**：卡片网格。已测算的档案直接显示"第几个月收回投入""要准备多少"、一条小曲线和下一步建议；访谈中的显示进度和还差哪几项；最后一张是新建档案
- **访谈工作台**：左边对话，右边档案卡片（按访谈阶段分组，每行带来源标签）。顶部写明"还差几项就能先算一下"，齐了按钮才亮
- **测算结果**：顶部一句话结论和四张数字卡片，其余见 12.3

### 12.5 字号和表格

- 正文 15px；对话和 AI 解读 16px；关键数字 34px
- 逐月明细表：数字统一用"元"、千分位、右对齐、等宽数字，方便一列列比较；当月亏钱用红色；"开始不亏钱""收回投入"两行用黄铜色底标出

### 12.6 技术做法

- 继续只用 Vant，**不引入第二套组件库**（如 Element Plus）：两套风格对不上，体积也翻倍。桌面专用的部件（侧边栏、表格、就地浮层、悬停提示）都很简单，自己写
- 布局切换以 CSS 媒体查询为主；需要换组件结构时（如档案卡片折叠还是常驻），用一个 `useBreakpoint()` 组合函数判断
- 图表仍用 ECharts，桌面端只调整尺寸和字号
- 路由、接口与手机端完全相同

### 12.7 需要后端配合

- 逐月明细表：评估快照里已经存了前 36 个月的每天卖、营业额、当月现金和手里的钱（`results.monthly`），接口直接返回即可
- "拖一拖"：需要一个假设性测算接口，计算引擎里的 `what_if` 已经实现

### 12.8 已确认的决定（2026-11-05）

- 三档宽度和 12.3 的差异对照
- 访谈工作台：档案卡片常驻右侧
- 测算结果的两栏布局和逐月明细表
- "拖一拖"放进第一版
- 不引入第二套组件库
