# 果园经营测算模型

2026-11-05 · 模板 `orchard` v1 · 引擎 `orchard-1`

## 适用范围

面向果农自身经营，首期支持已投产果园。一个档案覆盖明确起止日期的生产年或经营期，可含多个水果品种、采收批次和等级。不是小店供应商通讯录。

只计算经营期总账，假定全部销售款已收齐；不推算逐月回款、周转资金、幼树期、折旧、历史建园投入和多年回本。设备购置单列，未知显示未确认。

## 输入与缺项

参数使用 `schema_version: 2`，统一放在 `parameters.orchard`：

| 字段 | 内容 |
|---|---|
| `period` | 共同经营期起止日期；新表单预选当前完整公历年，由用户保存确认 |
| `audience` | 主要批发 / 主要零售 / 并重；不替代实际渠道占比 |
| `varieties` | 稳定ID的品种列表：名称、可选面积/采收期、总采收kg、采后损耗、等级、渠道、直接成本 |
| `shared_costs` | 本期土地租金、全园维护、其他共用支出 |
| `unpaid_labor` | 未付酬本人/亲属劳动的本期总估值 |
| `equipment` | 可选本期设备购置额，单列 |
| `supply` | 可选对外供货资料：规格、箱净重、供货期/量、起订量、发货范围、核实特点及依据 |

数值沿用 `base/pessimistic/optimistic/source/note`。缺失与明确零不同；没有农业基准默认值。允许未齐草稿；测算前要求每个品种的采收量、损耗、等级售出率、渠道售价/包装/物流/佣金、直接成本齐全，且共用支出、劳动估值已确认。

等级占比合计100%，每个等级内部批发/零售占比合计100%。默认统货一个等级；渠道可做一个或两个，比例由用户确认。各级ID唯一，访谈更正不得重建ID或丢失其他品种。

## 公式

- 可售重量 = 总采收量 × (1 − 采后损耗率)。
- 等级售出量 = 可售重量 × 等级占比 × 售出率。
- 渠道售出量 = 等级售出量 × 渠道占比。
- 渠道收入 = 渠道售出量 × 元/kg售价；未售出量收入为零。
- 渠道支出 = 售出kg × (包装元/kg + 物流元/kg) + 渠道收入 × 佣金率。
- 品种直接支出 = 农资 + 灌溉水电 + 已付人工 + 其他直接成本 + 渠道支出。
- 品种贡献 = 品种收入 − 品种直接支出，不任意分摊共用成本。
- 经营支出 = 所有品种直接支出合计 + 全园共用成本（仅一次）。
- 经营结余 = 总收入 − 经营支出。
- 扣家庭劳动后收益 = 经营结余 − 未付酬家庭劳动估值；已付人工不重复扣。

保本均价假设当前售出量、等级/渠道比例及佣金率不变，求所有渠道使用同一售价时覆盖经营支出所需价格：非佣金经营支出 ÷ Σ[渠道售出kg × (1 − 佣金率)]。不含家庭劳动估值；零销量、全损耗或有效分母为零时返回 `null` 并说明原因。

三档变化作用于产量、损耗、售出率、价格、成本，等级与渠道比例固定。未设置范围时三档一致，不自动编造波动。敏感性每次只改变一个有范围的数值，按经营结余变化绝对值排序。

## 单位与访谈

标准重量kg，价格元/kg，费用元/期。1斤=0.5kg，1吨=1000kg。`convert_orchard_unit`执行换算；箱价必须先确认水果净重，亩产必须确认该品种面积，日薪必须确认本期人数与天数。月薪须先确认本期实际支付月数，不默认全年。结果在字段备注保留原话、原单位与依据；服务端拦截未调用换算工具的相关写入。

访谈按期间、品种产收、主要客户、销售价格、成本/家庭劳动、确认测算推进；新信息有歧义时优先澄清。没有用户明确撤回指令不能清空字段。

## 验收基准

10,000kg采收、10%损耗、80%售出、6元/kg，收入43,200元；经营支出30,000元，结余13,200元；未付酬家庭劳动估值8,000元，调整后5,200元。

回归覆盖多品种/等级/渠道、无销量、全损耗、非法比例、范围方向、缺项、单位换算、历史快照不变、试算应用、权限、版本冲突、报告复用。纯引擎不依赖应用、文件、数据库、网络或AI，ID由调用方提供。

## 获客内容

用户显式选择采购商或消费者。采购商内容强调规格、供货期/量、起订量和合作；消费者内容强调选箱、下单与已核实采收日记。只传名称、生产地、品种名称和对外供货资料，内部成本利润不传给营销模型。

未知事实保留最多3个具体 `【待填：…】`，沿用填写、删行、预览、复制检查。采收期不从供货期推断，零售条件不从批发起订量推断；认证、糖度、包邮、时效均需依据。规则检查仅辅助，发布前仍由用户核实；无自动外部发布。
