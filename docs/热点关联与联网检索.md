# 热点关联与联网检索

内容创作先选择日常/供货切入点，再在下方「关联一个热点」选择可选热点。门店与果园分别展示相关候选；不选择时保留原来的写作流程。选择后可查看摘要、媒体和时间，生成时重新检索该标题，将实际取得的背景与切入点共同交给 DeepSeek。

## 来源与时效

- 默认在线来源为必应资讯 RSS 搜索，检索饮品点单、咖啡生活、果园果品相关报道；无需额外搜索密钥。搜索结果只表示近期资讯，不宣称全国热搜或小红书热榜排名。
- 仅收录有发布时间、近 7 天的报道；候选采集记录超过 24 小时不再展示或接受新生成请求。来源顺序是搜索相关性，不是热度排名。
- worker 每两小时更新。已验证邮箱用户进入页面时自动请求更新，也可点击更新；应用内两分钟复用一次刷新结果，数据库 advisory lock 防止 worker/API 同时采集。
- `CONTENT_NEWS_ENABLED=false` 可关闭默认候选资讯采集；`HOTAPI_BASE_URL` 可另外接入自部署 DailyHotApi。后者仅提供标题时明确记录为标题来源。单个来源失败不影响其他来源；全部失败展示更新失败提示。
- 候选经过词过滤、DeepSeek 营销适用性审核及去重；并非人工审稿。没有适合候选时显示空状态，不补造热点。

## DeepSeek 的实际联网方式

核对官方 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion) 与 [Tool Calls](https://api-docs.deepseek.com/guides/tool_calls) 文档：当前 API 支持函数工具，没有网页端同款的内置联网开关。本项目由服务端执行真实资讯检索，再将结果注入 DeepSeek 写作上下文；没有发送虚构的 `enable_search` 参数，也不声称模型读取了新闻全文。

生成任务保存 `hot_research` 和来源快照，页面在「这份草稿的依据」展示：

- `live`：本次联网取得与所选标题相关的摘要。
- `cached`：本次未获得新资料，使用选中时已有摘要并保留时间。
- `title_only`：未取得详情且原来源仅有标题，只围绕标题话题关联。

只向固定公共检索端点发请求，不抓取用户、模型或来源提供的网址；限制响应大小，拒绝 XML 实体。来源文本作为参考数据，不能覆盖系统指令。其他地区天气、品牌商品与活动不能视为本店事实，未知经营信息继续使用最多三处具体待填项。果园内部财务参数不发送给营销模型。

## 验证

`cd backend && uv run pytest tests/api/test_content_hot.py tests/api/test_hot_collection.py tests/api/test_content.py` 覆盖真实响应格式、时效过滤、来源保存、失败降级、档案隔离、重复请求和刷新复用。实际来源可用性和文案质量另以本地真实服务及浏览器验证，不用模拟结果冒充联网成功。

真实门店/果园生成记录见 `热点关联回归样例.json`，包含本次实际摘要、媒体、发布时间与检索时间，不含账户和会话信息。浏览器在1440、1000、390像素完成选择、生成、来源恢复；失败/空状态通过受控接口响应另行验证。
