## 启动与配置

按 `.env.example` 配置后运行 `docker compose up -d --build`。不要提交 `.env`，不要把配置完整输出到日志。worker 依赖 API 健康检查，迁移由 API 启动时完成。

`INTERVIEW_MODEL`、`REPORT_MODEL` 必须是当前账号可用模型。日配额默认每账号50次（访谈、报告、文案共用），按北京时间重置；失败请求也计次。每账号最多3个并发任务，同一档案的访谈串行；同一快照的报告请求复用在途任务。`AI_RUN_SECONDS` 控制任务总时限，`AI_REPORT_MAX_TOKENS` 限制报告输出；报告关闭隐藏思考，使用带含义的结果摘要并核对数字，首轮失败后重试不含数字的建议。在供应商控制台核对实际账单。

`CONTENT_NEWS_ENABLED=true` 默认使用必应资讯 RSS 采集近期行业报道；`HOTAPI_BASE_URL` 可叠加自行维护的 DailyHotApi。候选经主题白名单、风险词过滤和模型筛选；来源保存摘要与时间，无向量时按标题去重。生成前重新检索所选热点，失败时明确记录已有摘要或仅标题状态。源故障不影响日历和日常选题，尚未提供每日自动推送。

API 当前使用单个 Uvicorn 进程。AI 任务在进程内运行、状态写库；服务重启不自动重新执行工具。超过租期的请求标记失败，用户重新发送前先查看已记录数字。需要水平扩容时再将任务执行与事件订阅迁移到持久队列。

## 自动检查

`deploy/ci/checks.yml` 包含 GitHub Actions 的 PostgreSQL测试、空库迁移、Ruff、Vitest和构建任务。当前OAuth凭据缺少 `workflow` 权限，GitHub拒绝创建工作流，因此配置以模板交付；使用具备该权限的凭据后移到 `.github/workflows/checks.yml` 并推送即可启用。目前验证来自本地执行，尚无远程Actions通过记录。

## HTTPS

生产可在现有 Nginx 前使用 Caddy/受控反向代理自动管理证书，将域名转发到本机 `127.0.0.1:8080`。把 Compose HTTP 端口绑定为本机地址，避免直接暴露后端入口。配置域名后设 `APP_BASE_URL=https://域名`、`SESSION_COOKIE_SECURE=true`、`APP_ENV=production`。

如需从可信前置代理取得真实IP，应仅信任该代理地址，再调整Nginx的real_ip配置；不能直接信任客户端传入的X-Forwarded-For。部署前验证邮件链接、会话Cookie、限流及SSE不缓冲。

## 备份与删除

- `deploy/scripts/backup.sh /绝对路径/新备份.dump` 生成权限受限的备份，拒绝覆盖同名文件。
- `deploy/scripts/verify-backup.sh /绝对路径/备份.dump` 在独立临时库恢复并核对迁移版本，退出时删除临时库。
- 在线恢复必须先停写、另存当前备份，再由运营者明确执行 `pg_restore`，脚本不自动覆盖在线库。
- worker 每两小时彻底删除超过30天的软删除档案，并级联删除参数审计、快照、访谈、AI请求和草稿。未到期档案仍可恢复。
- 备份保留期限由运营方设定。删除在线数据不等于立即清除旧备份，上线协议需说明备份滚动过期方式。
